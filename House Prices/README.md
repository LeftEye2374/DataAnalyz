# House Prices — Advanced Regression Techniques
 
Второй проект в портфолио: предсказание цены дома на основе его характеристик. В отличие от Titanic (задача классификации), здесь решается задача **регрессии** — предсказание непрерывного числового значения (цены), плюс датасет значительно шире (79 признаков вместо 11) и требует более серьёзной работы с пропусками и feature engineering.
 
## Датасет
 
[House Prices - Advanced Regression Techniques](https://www.kaggle.com/c/house-prices-advanced-regression-techniques) (Kaggle).
 
Файлы: `train.csv` (1460 строк, 81 колонка, включая целевую `SalePrice`), `test.csv`, `data_description.txt` — текстовое описание всех признаков и их допустимых значений.
 
## Стек
 
- Python 3.12
- pandas, NumPy — обработка данных
- matplotlib — визуализация
- scikit-learn — модели, метрики
- CatBoost — планируется на следующем этапе
- Jupyter Notebook
## Прогресс
 
### 1. Загрузка и первичный осмотр данных
 
- Загрузка `train.csv`, проверка размерности (`.shape`), структуры (`.info()`), базовой статистики (`.describe()`).
- Создана рабочая копия датафрейма (`train_set_copy`) для дальнейшей обработки — исходный `train_set` сохранён нетронутым для сравнения.
### 2. Анализ пропущенных значений
 
Обнаружено 19 колонок с пропусками. Пропуски разделены на две принципиально разные категории — это ключевое отличие от Titanic, где пропуск почти всегда означал недостающую информацию.
 
**Категориальные признаки, где `NaN` означает осмысленное отсутствие характеристики** (согласно `data_description.txt`), а не ошибку данных:
 
| Колонка | Пропусков | Значение NaN |
|---|---|---|
| PoolQC | 1453 | нет бассейна |
| MiscFeature | 1406 | нет доп. построек |
| Alley | 1369 | нет доступа через переулок |
| Fence | 1179 | нет забора |
| MasVnrType | 872 | нет облицовки стен |
| FireplaceQu | 690 | нет камина |
| GarageType / GarageFinish / GarageQual / GarageCond | 81 | нет гаража |
| BsmtQual / BsmtCond / BsmtExposure / BsmtFinType1 / BsmtFinType2 | 37–38 | нет подвала |
 
**Обработка**: заполнены строковым значением `'None'`, чтобы сохранить смысловую нагрузку "признак отсутствует", а не удалять колонку или использовать статистику, не имеющую смысла для такого случая.
 
**Числовые/прочие признаки с реально недостающими данными:**
 
| Колонка | Пропусков | Обработка |
|---|---|---|
| LotFrontage | 259 | заполнено медианой |
| GarageYrBlt | 81 | заполнено 0 (гаража нет — см. GarageType) |
| MasVnrArea | 8 | заполнено 0 (облицовки нет — см. MasVnrType) |
| Electrical | 1 | заполнено модой (единичный случай) |
 
После обработки проверено: `train_set_copy.isnull().sum().sum() == 0`.
 
### 3. Анализ целевой переменной
 
- Построена гистограмма распределения `SalePrice`.
- Распределение скошено вправо (правый "хвост" из дорогих домов) — учтено для следующего этапа: планируется логарифмирование целевой переменной (`np.log1p`) перед обучением моделей, так как большинство алгоритмов регрессии работают лучше с приближенным к нормальному распределением.
## Ключевой вывод этапа
 
Главное отличие обработки пропусков в этом датасете от Titanic: **нельзя применять одну и ту же стратегию ко всем пропускам механически**. Прежде чем заполнять NaN медианой/модой, необходимо свериться с описанием датасета (`data_description.txt`) — часть пропусков являются не ошибкой, а полноценным значением категории ("признак отсутствует"), и их неверная обработка (например, удаление колонки или заполнение медианой) исказила бы смысл данных.
